# 生命演化数学实验室作品说明

## 创意来源

本作品来源于康威生命游戏。它把生命现象抽象为一个二维网格：每个格子只有“活”或“死”两种状态，每一代都根据周围 8 个邻居的数量决定下一代状态。作品希望用可操作的互动程序展示一个数学现象：非常简单的局部规则，也能产生稳定结构、周期振荡、移动图形和复杂群体变化。

## 数学原理

本作品把整张棋盘看成一幅由 0 和 1 组成的图像。第 \(t\) 代图像记作 \(X_t\)，第 \(r,c\) 个格子的状态记作：

\[
x_t(r,c)\in\{0,1\}
\]

其中 1 表示活细胞，0 表示死细胞。每个格子先计算周围 8 个邻居中有多少活细胞：

\[
n_t(r,c)=\sum_{i=-1}^{1}\sum_{j=-1}^{1}x_t(r+i,c+j)-x_t(r,c)
\]

生命游戏的核心可以写成一个算子 \(T\)：

\[
X_{t+1}=T(X_t),\qquad X_t=T^t(X_0)
\]

这句话的意思是：第 \(t+1\) 张图像不是提前画好的，也不是视频播放出来的，而是同一台“数学机器” \(T\) 对第 \(t\) 张图像重新计算得到的。第 \(t\) 代图像就是从初始图像 \(X_0\) 出发，把同一个算子连续使用 \(t\) 次。

每个细胞的下一代状态由邻居数量决定：

- 活细胞邻居少于 2 个时死亡，表示数量不足。
- 活细胞邻居为 2 或 3 个时继续存活。
- 活细胞邻居多于 3 个时死亡，表示过度拥挤。
- 死细胞邻居正好为 3 个时变为活细胞。

用小学生能理解的话说：每个小格子每一轮只看身边 8 个朋友。朋友太少会孤单，朋友太多会拥挤，刚好合适就能留下；如果一个空格子周围正好有 3 个朋友，它就会诞生新细胞。所有格子同时判断，所以不会出现“先动的格子影响后动的格子”的情况。

这个规则也可以理解成一场局部博弈：每个细胞都只和邻近 8 个位置发生关系，在“孤单、拥挤、刚好合作”的规则里决定下一轮命运。没有导演，没有预设路线，整体图案是由许多局部判断共同生成的。

程序把网格看成首尾相接的环面，边缘格子也能计算完整的 8 个邻居。实验面板记录每一代的活细胞数量、活细胞占比、出生数和死亡数，并绘制活细胞数量曲线。通过这些数据，可以比较不同初始密度、不同图形和不同随机种子下的演化差异。

不同现象可以用同一个算子语言解释：

| 现象 | 数学表达 | 直观解释 |
| --- | --- | --- |
| 稳定结构 | \(T(X)=X\) | 算完以后图像不变，说明进入固定点。 |
| 周期结构 | \(T^k(X)=X\) | 图像没有静止，但每隔 \(k\) 代回到原样。 |
| 移动结构 | \(T^k(X)\) 是平移后的 \(X\) | 代码没有写“向前飞”，整体移动从局部规则中涌现。 |
| 密度差异 | 同一 \(T\)，不同 \(X_0\) | 起点不同，活细胞曲线和最终结局可能不同。 |
| 长期复杂 | 多代后仍有出生和死亡 | 系统不快速收敛，简单规则能持续创造新结构。 |

## 实现过程

核心计算使用 Rust 编写，并通过 WebAssembly 在浏览器中运行。Rust 负责保存棋盘状态、执行生命游戏规则、放置典型图形、生成可复现实验初始状态，并输出统计数据。浏览器端使用 Vite 和原生 Canvas 绘制棋盘与折线图，打开页面后会自动运行“滑翔机发射器”动画代表性案例，不再弹出阻塞式说明框，而是直接在画布旁提示“点画布注入图形”。界面把主视觉空间优先留给演化画布，把场景条、注入图形按钮组、速度和运行控制围绕画布边缘布置，让评委像玩实时系统一样操作。右侧改为动态中文解说和紧凑数据证明，解释刚刚注入了什么、改变了哪个变量、下一代如何由 \(X_{t+1}=T(X'_t)\) 继续计算。页面下方保留完整数学说明、公式、案例意义和 CSV 导出功能。

程序支持五种典型图形：

- `block`：稳定结构，用于观察不变性。
- `blinker`：周期为 2 的振荡结构。
- `toad`、`beacon`、`pulsar`、`pentadecathlon`：不同大小、不同周期的振荡结构。
- `glider`：会移动的轻量结构，用于观察局部规则形成整体迁移。
- `lwss`、`mwss`、`hwss`：轻型、中型、重型飞船，大小和移动外形不同。
- `acorn`：初始很小但会变化很久的结构。
- `glider_gun`：滑翔机发射器，会持续产生新的滑翔机。

界面还提供“演示模式”和“实验场景”选择。页面默认入口改为“滑翔机发射器”：评委一打开就能看到新滑翔机持续产生，先感受到数学规则的动画冲击力，再通过画布点击注入新的扰动，理解画面不是视频，而是每一代重新“数邻居、套公式、生成下一代”的计算结果。原来画布上方的大段说明被移到右侧动态解说和底部长文档中，首屏把注意力留给画布。右侧会同步显示当前实验标题、实时结论、推荐注入、改变变量、预期观察和六年级版规则机器。完整 KaTeX 公式和更正式的算子说明放在页面底部长篇文档的进阶区，避免一打开页面就被复杂公式挡住理解。标题旁保留“开始演示”按钮，但它是辅助入口；主要入口是直接玩画布。右侧“实时数据证明”区域压缩显示代数、活细胞数量、出生数、死亡数和人口曲线，让观众看到视觉变化背后有可记录、可导出的实验数据。

页面最下方新增默认展开的长篇文档式解释说明，分为“这个项目是什么、规则机器怎样计算、为什么不是视频、实验场景墙分别证明什么、数据曲线怎样读、可以得出的数学结论”六节。长文先用适合小学六年级学生理解的语言解释，再补充“算子、固定点、周期轨道、涌现、初始条件敏感性、非快速收敛”等正式术语。评委如果只看首屏，可以快速理解；如果愿意向下阅读，也能获得完整项目说明。

实验场景扩展为约 20 个紧凑卡片，并把动画丰富、最有代表性的场景放在前面：滑翔机发射器、长期变化、飞船赛道、滑翔机移动、脉冲星花瓣、多振子剧场、密度三连、橡果长跑等。首屏只把最常用场景放在画布边缘场景条中，其余收入“更多场景”，避免抢走画布中心。每张卡片不仅加载场景，还显示推荐注入元素和观察任务：发射器、飞船、滑翔机类推荐注入稳定障碍物，周期类推荐注入滑翔机，密度类推荐注入稳定小岛，稳定结构推荐注入移动粒子。评委点击任意卡片一次，程序会自动设置棋盘、速度、种子或密度，并把注入按钮切到推荐工具。“密度三连”会自动依次比较稀疏、中等、拥挤三种随机初始条件，说明同一条公式在不同参数下可能得到不同结局。需要完整讲解时，演示模式按“选择场景、注入图形、暂停观察、读右侧解释”的玩法脚本运行，便于后续录制评审视频。

为了避免现场操作混乱，界面把运行状态明确分成“运行中”“已暂停”“已停止：第 0 代”和“空棋盘”。开始/暂停只负责继续或暂停当前计算；停止/重置会回到最近一次手绘或注入后的扰动起点；新增“恢复本案例”会清除扰动，回到当前场景原始配置。修改棋盘、种子或密度时，程序会立即停止旧运行并加载新的第 0 代；点击场景会立即切换并自动运行。画布点击会被解释为数学扰动：停止或暂停时点击是改变第 0 代 \(X_0\)，运行中点击是改变当前代 \(X_t\)。扰动后的图像记作 \(X'_t=X_t+P\)，下一代仍按同一公式 \(X_{t+1}=T(X'_t)\) 计算。评委点击一个孤立点后再开始，孤立点可能下一代消失，这不是程序丢失点击，而是因为它周围 `n = 0`，满足 `n < 2` 的死亡条件。

## 创新点

- 将数学规则、工程实现和实验数据记录放在同一个互动程序中。
- 随机初始状态由种子和密度共同决定，便于复现实验结果。
- 内置典型图形，能直接比较稳定、振荡和迁移三类现象。
- 页面打开后自动运行代表性案例，并用画布旁点击引导降低评委进入门槛。
- 标题旁提供全局演示入口，但主入口是直接点击画布参与实验。
- 主画布优先放大，实时数据证明压缩在右侧，把“看起来在变”和“数据确实在变”都保留在评审视野里。
- 画布边缘提供场景条、注入工具和运行控制，支持按场景推荐注入元素，让评委能亲手改变当前数学系统。
- 实验场景墙把约 20 个稳定、周期、移动、密度差异和复杂长期变化集中成一键实验，并把动画丰富案例放在最前面，降低现场操作成本。
- 右侧动态解说同步展示当前实验、实时结论和六年级版规则机器，让评委一边玩一边理解。
- 完整 KaTeX 公式放在页面底部进阶区，把生命游戏讲成“算子生成图像”，从 \(X_{t+1}=T(X_t)\) 解释每一帧为什么是实时计算结果。
- 底部长篇文档默认展开，先用小学生语言解释，再补充正式数学术语，降低理解门槛，也保留数学深度。
- 演示模式把关键实验组织成约 3 分钟玩法录屏式流程，适合展示“评委应该怎么玩”。
- 实时统计出生数和死亡数，让观察不只停留在动画效果，也能形成可分析的数据。
- CSV 导出可作为研究记录，支撑后续撰写报告或制作展示视频。

## 实验记录

建议提交前至少保留三组实验数据：

| 实验 | 初始条件 | 观察目标 | 记录方式 |
| --- | --- | --- | --- |
| 稳定性实验 | 放置 `block`，运行 20 代 | 活细胞数量是否保持不变 | 截图与 CSV |
| 周期实验 | 放置 `blinker` 或 `pulsar` | 图形是否按固定周期恢复 | 截图与 CSV |
| 密度实验 | 使用同一种子，比较 15%、26%、40% 初始密度 | 活细胞数量曲线差异 | CSV 折线图 |
| 长期变化实验 | 选择“长期变化”场景 | 是否持续出现出生和死亡 | 截图、CSV 与短视频 |

实际提交时，应使用程序导出的真实 CSV 数据补充表格，并选择代表性截图或 3 分钟以内视频展示运行过程。
